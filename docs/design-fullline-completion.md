# Design: ИИ-дополнение строк (full-line completion) для PascalABC.NET

## 1. Идея

Призрачный текст (ghost text) в редакторе VS Code: после курсора показывается
предложение продолжения строки/блока, подтверждается Tab. Предложения генерирует
локальная LLM (llama.cpp + модель Qwen 1.5B, дообученная на PascalABC.NET),
дополнение вычисляется по FIM-промпту (fill-in-the-middle). Ничего не уходит
в сеть: всё работает на машине пользователя.

## 2. Компоненты

| Компонент | Где живёт | Роль |
|---|---|---|
| `FullLineCompletionLspPlugin.dll` | репа `pascalabcnet_full_line_completion` | плагин LSP-сервера: регистрирует `IInlineCompletionProvider`, сам поднимает llama-server |
| `FullLineCompletionSetup.dll` | та же репа | консольный установщик: скачивает llama.cpp + модель, пишет паспорт установки |
| llama.cpp + модель | скачивается при установке | LLM-рантайм (~1 ГБ модели) |
| VS Code-расширение | репа `pascalabcnet_vscode` | хост: UI, команды, прогресс, деплой dll, политика обновлений |
| Модель | Hugging Face `PascalABCNET/Qwen-Coder-1.5B_Q4_K_M_full_line_completion` | веса `.gguf` + манифест `fullline-model.json` |

Поток запроса: провайдер редактора → `pascalabc/inlineCompletion` (зеркало
`textDocument/inlineCompletion` из LSP 3.18) → плагин (FIM-промпт,
`/tokenize`, `/v1/completions`, `/detokenize`) → llama-server.

## 3. Хранилище: почему вне расширения

Всё устанавливается в AppData, а не в папку расширения:

    %LOCALAPPDATA%\PascalABC.NET\
      llama.cpp\          llama-server.exe, *.dll ggml, модель.gguf,
                          fullline-setup.json, llama-server-state.json
      LspPlugins\         FullLineCompletionLspPlugin.dll

Решения и почему:

- **Вне папки расширения** — VS Code при обновлении заменяет папку расширения
  целиком; гигабайт модели не должен перекачиваться при каждом апдейте.
- **Каталог общий для всех хостов PascalABC.NET** (VS Code, IDE) — модель одна
  на машину; удаление компонентов в одном хосте выключает ИИ и в другом,
  о чём предупреждает диалог подтверждения.

Каталог «свой» распознаётся по маркеру `fullline-setup.json` (пишет setup).

## 4. Загрузка плагина в LSP-сервер

Сервер принимает `--plugins-dir <путь>` (можно несколько) и загружает сборки
`*LspPlugin.dll` при старте. Расширение передаёт `--plugins-dir
<AppData>\LspPlugins` только когда фича включена.

## 5. Управление llama-server (плагин)

`LlamaServerManager` внутри плагина — единый жизненный цикл для любого хоста:

- Внешний сервер: `PABC_LLM_URL` задан — используется как есть, ничего не
  спавнится. Иначе — свой llama-server из `fullline-setup.json`.
- Запуск: свободный порт, `--host 127.0.0.1 --parallel 1 --ctx-size 768
  --threads 4 --threads-batch 6 --flash-attn on -ngl 99`. Команда одна для всех
  устройств: на CPU флаги GPU молча игнорируются. Тюнинг принадлежит плагину
  (обновляется вместе с dll), из конфига берутся только пути.
- Готовность: опрос `/health` (503 — модель ещё грузится), таймаут 15 минут.
- Состояние: `llama-server-state.json` (pid, порт, время) — хосты читают его для
  прогресса и приборки. Осиротевший процесс прошлого запуска гасится по pid.
- Смерть вместе с LSP: Windows Job Object с `KILL_ON_JOB_CLOSE` — ядро гасит
  llama при любом завершении LSP-процесса (закрытие VS Code убивает сервер
  принудительно, `ProcessExit` в этом случае не срабатывает). На не-Windows —
  `ProcessExit`. Страховка — приборка по pid из state-файла.
- Логи: вывод llama по умолчанию глушится (иначе спам в канал вывода хоста),
  проходят только строки с ошибками; полный лог — `PABC_LLM_LOG=1`.

## 6. Жизненный цикл в VS Code

Единственный источник истины — настройка `pascalabc.fullLineCompletion.enabled`
(по умолчанию false). Галочка в настройках и команды палитры пишут одно и то же:
`включить/выключить`, `установить`, `обновить`, `удалить компоненты`,
`статус и диагностика`.

Установка (первое включение или явная команда):

1. Модальный диалог согласия.
2. Деплой dll из бандла VSIX в `AppData\LspPlugins` (с ретраями: Windows мгновение
   держит файл после остановки сервера).
3. Setup: прогресс-бар VS Code на NDJSON-событиях (`--progress json`), скачивание
   llama.cpp и модели. Модель — атомарно (`.partial` → rename), с проверкой
   sha256/размера; повторная установка не перекачивает имеющуюся.
4. Перезапуск LSP-сервера; прогресс загрузки модели — по state-файлу.

Все операции сериализованы цепочкой: галочка и палитра не могут запустить setup
параллельно. Перезапуск сервера пересоздаёт все клиентские регистрации
(команды NuGet и пр.) вместе с клиентом — иначе повторный старт роняет
IntelliSense.

## 7. Версии и обновления

- **dll плагина** — bundle-модель: dll лежит в VSIX (`fullline/`, собирается
  `scripts/import-fullline-plugin.ps1` из соседней репы или из клона по пину
  `scripts/fullline-plugin.ref` = тег репы плагина). При каждом
  старте (фича включена) dll перекладывается в `AppData\LspPlugins` — обновление
  расширения не требует переустановки.
- **Модель** — версионируется коммитом репозитория HF (revision = SHA коммита);
  манифест `fullline-model.json` описывает url/revision/размер/sha256. Рекомендуемый
  url/revision — константы релиза в `src/fullline.ts` (не настройки пользователя;
  для разработки — `PABC_FULLLINE_MODEL_URL`). При старте расширение сравнивает
  `modelUrl` из паспорта установки с рекомендуемым и предлагает «Обновить».
- **llama.cpp** — обновляется вместе с setup при переустановке компонентов.

Теги репы плагина — свои SemVer (`vMAJOR.MINOR.PATCH`), независимы от версий
VSIX; ставятся при изменении поведения dll/setup и служат точками пина для
воспроизводимой сборки. Текущий релиз — `v0.0.1` (экспериментальный, линия 0.x).
Старые теги `vsix-0.6.x` — исторические, новее не использовать.

Политика: обновление расширения автоматически обновляет dll; обновление модели
только с согласия пользователя (уведомление при старте).

## 8. Удаление

- **«Удалить компоненты»** (палитра): сначала останавливает LSP-сервер (иначе
  dll и llama-server.exe залочены — EPERM), ждёт реального выхода процесса,
  удаляет `llama.cpp` и `LspPlugins` с ретраями. Диалог предупреждает, что
  каталог общий для всех хостов.
- **Удаление расширения** (UI VS Code): hook `vscode:uninstall` (`uninstall.js`)
  сносит те же каталоги при первом старте VS Code после удаления. Ограничение
  платформы: hook срабатывает только на UI-удаление и только после перезапуска;
  `code --uninstall-extension` и удаление папки вручную его не вызывают
  (для этого есть тот же `uninstall.js` запущенный вручную).

## 9. Безопасность

llama-server слушает только `127.0.0.1`; сеть используется лишь при установке
(GitHub — llama.cpp, Hugging Face — модель). Телеметрии нет.

## 10. Известные ограничения

- Если llama-server упадёт посреди сессии, авто-возрождения нет — лечится
  выключением/включением галочки. Добавить при необходимости.
- Кнопка «Cancel» в модальных диалогах принадлежит VS Code и следует языку
  его интерфейса.
- Полный вывод llama доступен только через `PABC_LLM_LOG=1`.

## 11. Карта репозиториев

- `pascalabcnet/pascalabcnet_full_line_completion` — этот док, плагин, setup.
  Ветка `master`, теги `vX.Y.Z` — точки пина для сборки VSIX (текущий `v0.0.1`).
- `pascalabcnet/pascalabcnet_vscode` — хост: `src/fullline.ts` (жизненный цикл),
  `src/extension.ts` (интеграция, команды), `uninstall.js`,
  `scripts/import-fullline-plugin.ps1`, `scripts/fullline-plugin.ref`.
- `pascalabcnet/pascalabcnet` (сабмодуль) — контракты (`CodeCompletionContracts`,
  `LSP_PluginsAPI`) и сам LSP-сервер с механикой `--plugins-dir`.
- Hugging Face `PascalABCNET/Qwen-Coder-1.5B_Q4_K_M_full_line_completion` —
  модель и манифест.
